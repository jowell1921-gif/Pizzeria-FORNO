# 0010 — Administración del negocio (Fase 8B)

Fecha: 2026-11-08

Completa la fase 8: el personal autorizado gestiona la carta, el local, las promociones y FORNO CLUB desde el panel.

| Tema                    | Decisión                                                                                                                                                                                                                                                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Permisos                | Un permiso por área: `catalog:manage`, `settings:manage`, `promotions:manage`, `loyalty:manage`, `customers:read` y `audit:read`. Salen de la base de datos; la interfaz solo oculta lo que el rol no puede usar                                                                                                         |
| Auditoría               | Toda escritura registra actor, acción, entidad y valores **antes y después** en la misma transacción (`recordAudit`). Pausar los pedidos se registra como `store.pause`. El registro es solo de lectura (`GET /admin/audit`)                                                                                             |
| Ediciones parciales     | `PATCH` solo cambia lo enviado. Los valores por defecto se aplican al **crear**, no al editar (un test lo protege: editar el precio no reactiva un producto agotado ni borra sus alérgenos)                                                                                                                              |
| Productos               | Borrado lógico (los pedidos antiguos conservan su copia del nombre y el precio) y restauración. Los importes viajan como texto decimal. Las opciones se sincronizan por `id`: se conservan las existentes, se desactivan las retiradas y se borran los grupos que desaparecen                                            |
| Imágenes                | Ruta propia (`/image/…`) o URL `https`. La subida (`POST /admin/uploads/product-image`) valida el **contenido** (JPEG, PNG o WebP por sus primeros bytes, no por el tipo declarado) y limita a 3 MB. Sin `SUPABASE_SECRET_KEY` responde `503 STORAGE_NOT_CONFIGURED` y el panel lo explica                               |
| Clave secreta           | `SUPABASE_SECRET_KEY` solo existe en el `.env` del backend y únicamente se usa para Storage. Nunca llega al navegador ni a Flutter                                                                                                                                                                                       |
| Horarios y zonas        | El horario semanal se reemplaza completo (sin solapes). Un código postal pertenece a una sola zona. Debe quedar activa al menos la recogida o el reparto                                                                                                                                                                 |
| Promociones automáticas | Campo `automatic`: se aplican solas, sin código, cuando se cumplen las condiciones. Si el cliente escribe un cupón, el cupón gana; las recompensas se suman. Al crear el pedido se vuelve a evaluar con bloqueo de fila: con un límite de usos, solo los primeros lo consiguen y el resto recibe `409 PROMOTION_CHANGED` |
| Puntos                  | No hay edición directa del saldo: los ajustes pasan por el libro de movimientos con motivo obligatorio. La regla (puntos por euro, caducidad) es configurable                                                                                                                                                            |
| Interfaz                | Formularios con etiquetas, errores con lenguaje claro (por ejemplo, «Algún código postal ya pertenece a otra zona») y navegación del panel por rol                                                                                                                                                                       |

## Cambios posteriores

| Tema                         | Decisión                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| «Hazte administrador» (demo) | `PUT/DELETE /me/admin-role`: el propio usuario se concede o se quita el rol ADMIN para poder ver todo el panel. Es una **excepción de demostración** a la regla de que el cliente no puede cambiar su rol: solo funciona si `SELF_ADMIN_ENABLED` está activo (por defecto **sí**, también en producción, porque la web es una demostración que cualquiera debe poder probar; con `false` responde `403 SELF_ADMIN_DISABLED`), solo afecta al propio usuario, solo toca el rol ADMIN y queda en la auditoría (`role.self-grant` / `role.self-revoke`). El perfil informa de si está disponible (`selfAdminAvailable`) |
| Ventana de oferta            | Se muestra una vez a quien entra sin ningún rol y con el perfil completo; la respuesta se recuerda en el navegador. Explica la diferencia entre la web de clientes y el panel del personal. Hay además un botón en «Mi cuenta»                                                                                                                                                                                                                                                                                                                                                                                       |
| Cabecera                     | Junto al carrito, el personal ve «Panel del personal» (la cocina, su pantalla) en lugar de «Pedir ahora»                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Cocina a domicilio           | La cocina entrega el pedido al repartidor (`READY → OUT_FOR_DELIVERY`) y deja de verlo; el personal lo cierra. Antes quedaba «esperando al repartidor» para siempre en la pantalla de cocina                                                                                                                                                                                                                                                                                                                                                                                                                         |

**Si algún día FORNO se usa como negocio real:** pon `SELF_ADMIN_ENABLED=false`; si no, cualquier cliente podría ver los datos de los demás.

## Para activar la subida de fotos (manual)

1. En Supabase, **Storage → New bucket**: nombre `products`, marcado como **público**.
2. En **Project Settings → API Keys**, copia la clave _secret_ (`sb_secret_…`) y ponla solo en `backend/.env` como `SUPABASE_SECRET_KEY`. No la pegues en el chat, en Git ni en el frontend.
3. Reinicia el backend.
